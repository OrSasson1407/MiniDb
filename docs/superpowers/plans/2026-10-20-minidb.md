# MiniDb Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** לבנות מנוע מסד נתונים קטן ב-C# עם אחסון בדפים, buffer pool, B+ tree, WAL עם התאוששות, API בקוד, ושאילתות SQL בסיסיות.

**Architecture:** שכבות `Storage → Index/Transactions → Query → Api`, כאשר כל שכבה תלויה רק בשכבה שמתחתיה ומתקשרת דרך interfaces. הנתונים נשמרים בקובץ `*.mdb` של דפים בגודל 4096 בייט, והשינויים נרשמים ב-`*.wal` לפני commit.

**Tech Stack:** C# / .NET 8, xUnit, BenchmarkDotNet, Microsoft.Data.Sqlite (רק ב-benchmarks, להשוואה).

**Spec:** [docs/superpowers/specs/2026-10-20-minidb-design.md](../specs/2026-10-20-minidb-design.md)

## Global Constraints

- .NET 8, `<Nullable>enable</Nullable>` בכל הפרויקטים.
- `TreatWarningsAsErrors` ב-`MiniDb.Core` ו-`MiniDb.Tests`.
- גודל דף: `PageSize = 4096`. buffer pool ברירת מחדל: `256` דפים.
- Magic של קובץ הנתונים: `MINIDB01` (8 בייט ASCII). גרסת פורמט ראשונה: `1`.
- מפתח ראשי: `Int64` בלבד. מחרוזת: UTF-8 עם prefix של אורך `UInt16`.
- תנאי WHERE יחיד. אופרטורים: `=`, `<`, `<=`, `>`, `>=`.
- כל פונקציה עד כ-30 שורות. קובץ אחד לכל טיפוס ציבורי.
- כל `commit` מסתיים בשורה: `Co-Authored-By: Claude Haiku 5.5 <noreply@anthropic.com>`.

## Review Focus

1. פתיחת קובץ שלא קיים או קובץ שאינו מסד נתונים (magic שגוי) → שגיאה ברורה, לא קריסה.
2. מחרוזת עם תווים עבריים/Unicode ומחרוזת ארוכה מדי לדף יחיד → UTF-8 מדויק, ושגיאה ברורה כשהערך גדול מדי.
3. הכנסה עם מפתח שכבר קיים → `DuplicateKeyException`, והטבלה לא משתנה.
4. מחיקה של מפתח שלא קיים → `false`, לא חריגה.
5. WAL עם רשומה חתוכה בסוף הקובץ אחרי קריסה → מתעלמים ממנה, והטרנזקציות שחויבו נשמרות.
6. טרנזקציה שמלכלכת יותר דפים ממה שה-buffer pool מכיל → `BufferPoolFullException`, לא גידול שקט בזיכרון.

כל שורה מקבלת בדיקה בטאסק שבבעלותו (ראו `[Review]` בכל טאסק רלוונטי).
